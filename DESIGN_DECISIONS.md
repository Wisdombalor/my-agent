# My Agent design direction
Scope: refine the existing local property-management app, preserving listing CRUD, search/filter/sort, sample imagery, themes, and browser storage.
Audience inferred from README: a Nigerian agent managing a small property portfolio. No interviews or analytics supplied.
Alternatives assessed before implementation: marketplace hero with featured property (distracts from management); permanent sidebar (unnecessary for one view); compact portfolio workspace (selected, puts search and listings first).
Palette: paper #f4f7f6, surface #ffffff, ink #15372d, muted #52655e, green #16704d, divider #dbe4df. Retain existing sans families, use hierarchy and photography rather than decorative effects.
Layout: compact header, visible page heading and local-save explanation, four compact metrics in one divided strip, search plus expandable filters, result count/sort, image-led cards. Two metric columns on narrow screens.
Contract: no new destinations. Search/filter/sort changes listings immediately. Filters toggle at every size and aria-expanded matches visibility. Explicit details button is keyboard operable; edit/delete do not open details. Native dialogs retain Escape and focus restoration. Existing validation and success/error feedback remain. Empty data stays empty across reload.
Motion: no animation on search, filters, metrics, or keyboard actions. Occasional pointer-opened dialog uses existing 250ms opacity/transform entrance, immediate close for reliable native focus behavior. Toast uses 220ms opacity/transform transition. No decorative loops. Reduced motion removes movement. Press feedback is immediate.
Responsive: auto-fit cards, minmax(0,1fr) controls, 48px mobile targets, 16px touch inputs, dynamic dialog height, contained overlay scrolling. No new infrastructure, deployment, Figma or media generation.
Research: inspect actual first-use interface and source; targeted external pattern research is unnecessary for this bounded refinement. No competitive or user research claims.

## Landing-page extension, 8 November
User requests an explanatory landing page with changing property photos, plus a sort-select fit correction. Saved ViV grid preference is relevant; the exact recalled website remains unconfirmed. Choose a split introduction and six-tile asymmetric mosaic rather than a full-screen carousel (only one photo visible) or full-grid wall behind text (reduces readability). Keep workspace as workspace.html and make index.html the introduction. Header and primary CTA link directly to the workspace; brand provides the return home. No forced onboarding or visit gate.
Copy: “A clearer view of every property.” Explain exploring rental/sale listings and organizing details. Existing bundled images are illustrative sample properties, not verified marketplace stock.
Motion: premium/calm image rhythm; one of six tiles changes per 1.8 seconds, each crossfade 600ms, same-site existing easing. Initial hold 2.8 seconds. No flashes, moving text or mandatory entrance delay. Pause/resume is a real button. Reduced-motion starts static; page visibility and offscreen state suspend rotation. Decode next photo before fading. No new libraries or generated assets. Override blanket keyboard-motion suppression only for the decorative mosaic so pause/resume can operate from a keyboard; reduced-motion still wins.
Select: keep native semantics, remove platform appearance, inset SVG chevron, reserve 2.75rem inline-end space, widest option fits. Responsive sort row gets full available width on phones.
Acceptance: landing to workspace and home return; direct workspace reload; pause freezes image swap state; resume restarts; no page overflow at 320/390/768/1280; sort longest option fits with clear arrow inset; existing filtering/sorting continues. Source and actual browser evidence kept distinct.

## Photo destinations and deletion feedback correction
The user explicitly removed pause/play controls and requested direct listing navigation. Supersedes the prior visible pause requirement. Shared property-data.js supplies identical sample IDs to both pages. Landing uses current saved properties when present, with each tile's image, name and URL updated together. Hover/focus/touch settles transitions so the clickable target is stable. Empty saved portfolios hide the gallery. Native links target workspace.html?listing=ID; the workspace opens the requested details, handles missing IDs with a message, and clears the query on close.
Deletion feedback: concise success title, two-line property name, Undo for 8 seconds and dismiss. Pointer/focus/background hold the notification timer. Save failure restores the deleted entry and produces no success notification. Undo restores the entry and persists it; failed restore save rolls back the in-memory restore. No user listings deleted during browser verification.
